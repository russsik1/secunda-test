## План тестирования

### 0) Общая инфраструктура тестов (перед написанием кейсов)
- [ ] **Тестовый раннер**: `pytest`
- [ ] **Async поддержка**: `pytest-asyncio` (или `anyio`)
- [ ] **HTTP клиент**: `httpx` (ASGITransport) для вызова FastAPI без реального порта
- [ ] **Изоляция БД**:
  - вариант A: отдельная тестовая БД в docker compose (предпочтительно)
  - вариант B: отдельная схема в той же БД (если удобнее)
- [ ] **Fixtures**:
  - `settings` (API_KEY, DSN тестовой БД)
  - `async_engine` / `async_sessionmaker`
  - `db_session` (transaction rollback на тест)
  - `client` (AsyncClient по app)
  - `seed_minimal` (быстрые фикстуры данных: 1 здание, 3 активности (дерево), 2 организации)
- [ ] **Миграции в тестах**:
  - перед пакетом тестов: `alembic upgrade head`
  - после: очистка (drop schema/database) или пересоздание

## 2) `app/core/security.py` (API Key)
### Юнит‑кейсы
- [ ] **Без `X-API-Key` → 401**
- [ ] **Неверный `X-API-Key` → 401**
- [ ] **Верный `X-API-Key` → OK (не падает)**

### Интеграция (через HTTP)
- [ ] **`/health` без ключа → 200**
- [ ] **Любой `/buildings/*` без ключа → 401**
- [ ] **Любой `/organizations/*` без ключа → 401**
- [ ] **С ключом → 200**

## 3) `app/db/models.py` (схема + ограничения)
### Юнит/интеграция БД
- [ ] **Ограничение глубины**: `activities.level` < 1 или > 3 → ошибка (CHECK)
- [ ] **UNIQUE (parent_id, name)**: попытка дубля → ошибка
- [ ] **FK поведение**:
  - [ ] удаление `organization` → каскадом удаляются `organization_phones` и строки M2M
  - [ ] удаление `activity` → каскадом удаляются строки M2M
  - [ ] удаление `building` при наличии организаций → запрещено (RESTRICT)
- [ ] **Индексы существуют** (опционально, если проверяем через инспектор SQLAlchemy)

## 5) `scripts/data_gen.py` (генерация тестовых данных)
### Интеграция
- [ ] **Первый запуск** добавляет здания/активности/организации
- [ ] **Повторный запуск (идемпотентность)** не создаёт дублей:
  - [ ] buildings по `address`
  - [ ] organizations по `name`
  - [ ] activities по `(parent_id, name)`
- [ ] **Содержимое данных**:
  - [ ] у организаций есть 1–3 телефона
  - [ ] у организаций есть 1–2 активности
  - [ ] активности создаются ровно в 3 уровня

## 6) `app/api/buildings/*`
### Интеграция (HTTP)
- [ ] **`GET /buildings` возвращает список**
- [ ] **Пагинация**:
  - [ ] `limit=1` → 1 элемент
  - [ ] `offset` сдвигает выборку
  - [ ] валидация `limit`/`offset` (минимум/максимум) → 422
- [ ] **Схема ответа** соответствует `BuildingOut` (id/address/lat/lon)

---

## 7) `app/api/activities/*`
### Интеграция (HTTP)
- [ ] **`GET /activities` возвращает список**
- [ ] **Сортировка**: по `level`, затем `id` (проверка порядка на фикстурах)
- [ ] **Пагинация** и валидация `limit/offset` → 422
- [ ] **Схема ответа** соответствует `ActivityOut`

---

## 8) `app/api/organizations/*`
### Интеграция (HTTP)
#### 8.1 `GET /organizations/{id}`
- [ ] **Существующий id → 200** и полный объект:
  - [ ] `phones` как `list[str]`
  - [ ] `building` вложен
  - [ ] `activities` вложены
- [ ] **Несуществующий id → 404**

#### 8.2 `GET /organizations/by-building/{building_id}`
- [ ] **Возвращает только организации здания**
- [ ] **Сортировка по `name`**
- [ ] **Пагинация** `limit/offset`

#### 8.3 `GET /organizations/by-activity/{activity_id}`
- [ ] **Только организации, у которых есть именно эта activity**
- [ ] **Пагинация**

#### 8.4 `GET /organizations/search/by-activity-tree/{activity_id}`
- [ ] **Root activity (уровень 1) → включает потомков уровней 2–3**
- [ ] **Activity уровня 2 → включает уровень 2 + уровень 3**
- [ ] **Activity уровня 3 → только уровень 3**
- [ ] **Не уходит глубже 3 уровней** (регрессия)
- [ ] **Пагинация**

#### 8.5 `GET /organizations/search/by-name?q=...`
- [ ] **Поиск по подстроке** (case-insensitive)
- [ ] **Пустой `q` → 422**
- [ ] **Пагинация**

#### 8.6 `GET /organizations/geo/box`
- [ ] **Корректный прямоугольник возвращает ожидаемые организации**
- [ ] **Пустой результат → пустой массив**
- [ ] **Граничные значения** (точно на границе) включаются

#### 8.7 `GET /organizations/geo/radius`
- [ ] **radius_km минимальный/максимальный** (валидация) → 422
- [ ] **Организации в радиусе возвращаются**
- [ ] **Организации вне радиуса не возвращаются**
- [ ] **Пустой результат → пустой массив**
